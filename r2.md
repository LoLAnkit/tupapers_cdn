# R2 Asset CDN — Design & Setup Plan

This document is the single source of truth for the **TUpapers asset CDN**: a Cloudflare R2 bucket that stores every notes image / figure / diagram used across all courses, served from `https://cdn.tupapers.com`.

The pipeline lives in a **separate repository** (the "asset repo"), independent from this Eleventy site. This site only *consumes* the generated `manifest.json` to build image URLs at compile time.

---

## 1. Goals

| Goal | How it's met |
|---|---|
| Automatic cache busting | Content hash in the **filename** (`name.7e8d3c41.webp`). New bytes → new hash → new URL. |
| Immutable CDN URLs | Hashed files are served with `Cache-Control: public, max-age=31536000, immutable`. |
| Small payloads | PNG/JPG → WebP + lossless/lossy optimization via `sharp`. |
| Easy lookup at build time | A flat `manifest.json` maps a stable logical path → hashed CDN path. |
| Scales cleanly | Bucket keys mirror the site taxonomy: `program/semester/subject/notes/...`. Adding BBA/BBS/BIT is just new folders. |
| No rework later | Folder names are **never** hashed, so keys stay human-readable and stable forever. Only the file's basename carries the hash. |

**Non-goal:** hashing folder names. Folders are permanent, human-readable, and mirror the website URL structure. Only filenames change when content changes.

## 2. Analyzed source structure (this site)

Notes assets are attached per-subject. The real nesting on this site is:

```
_src/course/<program>/<semester|year>/<subject>/notes/
```

- **Programs:** `bba, bbm, bbs, bca, bhm, bit, bitm, bsw, bttm, csit`
- **Level segment:** `first-semester` … `eighth-semester`
  - Exceptions: **bbs** and **bsw** use `first-year` … `fourth-year`
- **Subject:** e.g. `computer-fundamental`, `digital-logics`, `programming-in-c`

So a diagram for the *Computer Fundamentals* notes in BCA 1st semester logically belongs under:

```
bca/first-semester/computer-fundamental/notes/...
```

This taxonomy is what the R2 bucket keys will mirror exactly.

---

## 3. Bucket key design (the important part)

**Rule:** `program / semester / subject / notes / <category> / <filename>.<hash>.webp`
- only diagram for now
- Every path segment except the final filename is a clean, permanent folder.
- Only the **filename** gets the 8-char content hash.

### Examples

```
bca/first-semester/computer-fundamental/notes/diagram/addressing-modes.7e8d3c41.webp
bca/first-semester/digital-logics/notes/diagrams/k-map-4var.a91f0cde.webp
bbs/first-year/business-english/notes/diagram/tense-forms.5c2b7e10.webp
csit/third-semester/data-structure/notes/diagram/avl-rotation.0f3a9b22.webp
```

### Why this and not the other options

- **Mirrors the website URL** → mentally trivial to trace an image back to its page.
- **Prefix-scannable** → `aws s3 ls .../bca/first-semester/` lists everything for a semester. Cloudflare's dashboard browser groups by "/" so it behaves like folders.
- **No collisions** → same filename in two subjects lives under different prefixes.
- **Future courses just add a top-level prefix** — zero migration.

### Reserved top-level prefixes (optional, future-proofing)

Keep course assets under `course/` if you ever want to store non-course assets (blog, ads, og-images) in the *same* bucket without clashing:

```
course/bca/first-semester/computer-fundamental/notes/figures/addressing-modes.7e8d3c41.webp
blog/tribhuvan-university.9a1c...webp
og/bca-computer-fundamental.4d2e...webp
```

**Recommendation:** adopt the `course/` prefix from day one. It's cheap now and prevents a rename later. The rest of this doc assumes it. (ok follow this)

## 4. Content hashing strategy

- Hash algorithm: **SHA-256** of the **final optimized WebP bytes** (not the source PNG). Hash after optimization so identical output = identical hash.
- Take the **first 8 hex chars**. 8 hex chars = 32 bits ≈ 4.3B values — far more than enough for a few thousand images; collision risk is negligible and the manifest step detects any collision anyway.
- Filename format: `<slug>.<hash>.webp`
  - `slug` = kebab-case, ASCII only, no spaces. `Addressing Modes.png` → `addressing-modes`.
- Because the hash comes from bytes, re-running the pipeline on unchanged images produces the **same** filename → idempotent, no needless re-uploads.

```
addressing-modes.png  ──optimize──►  webp bytes  ──sha256[:8]──►  7e8d3c41
                                                    └────────────►  addressing-modes.7e8d3c41.webp
```

Edit the image later → different bytes → `addressing-modes.f14d2ea9.webp` → every browser/Cloudflare cache is bypassed automatically.

## 5. Image processing workflow

```
source image (png/jpg/webp/svg)
   │
   ▼  (1) normalize: strip metadata, auto-orient, optional max-width clamp
   │
   ▼  (2) convert → WebP (sharp)     svg passes through untouched
   │        - photos: quality 78, effort 5
   │        - graphics/diagrams: near-lossless or lossless
   │
   ▼  (3) sha256(webp bytes)[:8]  →  hash
   │
   ▼  (4) rename: <slug>.<hash>.webp
   │
   ▼  (5) upload to R2  (skip if key already exists)
   │        Cache-Control: public, max-age=31536000, immutable
   │        Content-Type: image/webp
   │
   ▼  (6) record in manifest.json  (logical path → hashed key)
```

Notes:
- **SVG** should not be rasterized. Optimize with `svgo` and hash the optimized SVG bytes; keep the `.svg` extension.
- Keep a `--dry-run` flag to preview without uploading.
- Uploads are **content-addressed**, so re-uploading the same bytes is a no-op (check via `HeadObject` first).

## 6. Manifest schema

The manifest is the contract between the asset repo and this Eleventy site. Keep it **flat and boring**.

Key = the **logical (pre-hash) path**, relative to the bucket root, using the *original* filename.
Value = the **actual uploaded key** (with hash).

`manifest.json`:

```json
{
  "version": 1,
  "generatedAt": "2026-07-21T00:00:00Z",
  "cdnBase": "https://cdn.tupapers.com",
  "assets": {
    "course/bca/first-semester/computer-fundamental/notes/figures/addressing-modes.webp":
      "course/bca/first-semester/computer-fundamental/notes/figures/addressing-modes.7e8d3c41.webp",

    "course/bca/first-semester/digital-logics/notes/diagrams/k-map-4var.webp":
      "course/bca/first-semester/digital-logics/notes/diagrams/k-map-4var.a91f0cde.webp"
  }
}
```

Why key by logical path (not by hash):
- Templates reference a **stable, human name** (`.../addressing-modes.webp`) that never changes.
- The pipeline swaps the hashed target underneath. Templates don't change when an image is updated.

Optional richer value (if you later want width/height for `<img>` to prevent layout shift):

```json
"course/bca/.../addressing-modes.webp": {
  "key": "course/bca/.../addressing-modes.7e8d3c41.webp",
  "width": 1200,
  "height": 640,
  "bytes": 41822
}
```

Design the consumer (section 9) to accept both shapes, or commit to the rich shape now. **Recommendation: use the rich object shape from day one** — width/height eliminate CLS and cost nothing to store.

## 7. The separate asset repository

A standalone Node.js CLI project. Industry-standard, boring, dependable stack — nothing exotic to maintain.

### Stack

| Concern | Choice | Why |
|---|---|---|
| Runtime | Node.js 20+ (ESM) | LTS, native `fetch`, stable. |
| Image processing | [`sharp`](https://sharp.pixelplumbing.com/) | De-facto standard; libvips-fast; great WebP support. |
| SVG optimization | `svgo` | Standard SVG optimizer. |
| R2 upload | `@aws-sdk/client-s3` (v3) | R2 is S3-compatible; official SDK, `HeadObject`/`PutObject`. |
| CLI | `commander` (or just `node --run`) | Simple flag parsing. |
| Config | `.env` via `dotenv` | Keeps secrets out of code. |
| Concurrency | `p-limit` | Throttle parallel uploads. |
| Lint/format | ESLint + Prettier | Standard hygiene. |

> Alternative to the AWS SDK: **`rclone`** or **`wrangler r2 object put`** for the upload step. The AWS SDK keeps everything in one Node process and gives you `HeadObject`-based skip logic, so it's the recommended path. `rclone` is a good fallback for bulk one-off syncs.

### Repo layout

```
tupapers-assets/
├─ README.md
├─ package.json
├─ .env.example
├─ .gitignore
├─ .eslintrc.json
├─ src/
│  ├─ index.js          # CLI entry (commander): build | upload | sync | prune
│  ├─ config.js         # loads .env, validates, exports R2 client + constants
│  ├─ discover.js       # walk source/ → list of source images
│  ├─ optimize.js       # sharp/svgo → optimized bytes + dimensions
│  ├─ hash.js           # sha256(bytes)[:8]
│  ├─ keys.js           # build logical + hashed R2 keys from a source path
│  ├─ upload.js         # HeadObject (skip if exists) → PutObject w/ cache headers
│  ├─ manifest.js       # read/merge/write manifest.json
│  └─ prune.js          # (optional) delete orphaned/old-hash objects
├─ source/              # RAW input images, mirrors the course taxonomy
│  └─ course/bca/first-semester/computer-fundamental/notes/figures/addressing-modes.png
├─ dist/                # optimized files written locally before upload (gitignored)
└─ manifest.json        # generated output — committed & published
```

### `source/` mirrors the taxonomy

You drop raw images into the **same folder shape** as the bucket, using **original (un-hashed) names**:

```
source/course/bca/first-semester/computer-fundamental/notes/figures/addressing-modes.png
```

The pipeline derives everything else. You never type a hash by hand.

### npm scripts (`package.json`)

```jsonc
{
  "type": "module",
  "scripts": {
    "build":  "node src/index.js build",   // optimize → dist/, update manifest (no upload)
    "upload": "node src/index.js upload",   // upload dist/ to R2 (skips existing)
    "sync":   "node src/index.js sync",     // build + upload in one shot
    "prune":  "node src/index.js prune",    // remove orphaned objects (dry-run by default)
    "lint":   "eslint src"
  }
}
```

Typical loop: drop images into `source/` → `npm run sync` → commit the updated `manifest.json` → this site rebuilds against it.

## 8. R2 + custom domain configuration

### One-time Cloudflare setup

1. **Create the bucket** — R2 → *Create bucket* → name `tupapers`. Pick a location hint near your audience.
2. **Connect the custom domain** — Bucket → *Settings* → *Public access* → *Connect Domain* → `cdn.tupapers.com`. Cloudflare auto-creates the DNS record and TLS cert. (Requires `tupapers.com` to be on Cloudflare DNS.)
   - Do **not** use the `r2.dev` public URL in production — it's rate-limited and not meant for real traffic. The custom domain is served through Cloudflare's CDN with full caching.
3. **Create a scoped API token** — R2 → *Manage API Tokens* → token with **Object Read & Write** on **only** the `tupapers` bucket. This yields:
   - Access Key ID
   - Secret Access Key
   - Account ID → endpoint `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`

### `.env.example` (asset repo)

```dotenv
R2_ACCOUNT_ID=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
R2_ACCESS_KEY_ID=xxxxxxxxxxxxxxxxxxxxxxxx
R2_SECRET_ACCESS_KEY=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
R2_BUCKET=tupapers
R2_ENDPOINT=https://<R2_ACCOUNT_ID>.r2.cloudflarestorage.com
CDN_BASE=https://cdn.tupapers.com
```

Never commit `.env`. Commit only `.env.example`.

### Cache & CORS

Because filenames are content-hashed, everything is safe to cache forever:

```
Cache-Control: public, max-age=31536000, immutable
```

Set this **per object on upload** (in `PutObject`). Optionally add a Cloudflare Cache Rule for `cdn.tupapers.com/*` with a long Edge TTL as a belt-and-suspenders.

CORS is only needed if JS fetches the images (e.g. `<canvas>`), not for plain `<img>`. If needed, add a bucket CORS policy allowing `GET` from `https://tupapers.com` and `https://www.tupapers.com`.

## 9. Eleventy integration (this site consumes the manifest)

The site needs **read-only** access to `manifest.json`. Two options:

- **A. Commit `manifest.json` into this repo** (simplest, versioned, offline builds). Recommended.
- **B. Fetch it at build time** from `https://cdn.tupapers.com/manifest.json` using `@11ty/eleventy-fetch` (cached). Use if you want the site and assets fully decoupled.

### Global data loader

`_src/_data/cdn.js`:

```js
// Loads the asset manifest and exposes a resolver.
import fs from "node:fs";

const manifest = JSON.parse(fs.readFileSync("./manifest.json", "utf8"));
const base = manifest.cdnBase; // "https://cdn.tupapers.com"

// Accepts a logical path, returns the full hashed CDN URL.
export default {
  base,
  resolve(logicalPath) {
    const entry = manifest.assets[logicalPath];
    if (!entry) {
      throw new Error(`[cdn] asset not in manifest: ${logicalPath}`);
    }
    const key = typeof entry === "string" ? entry : entry.key;
    return `${base}/${key}`;
  },
  meta(logicalPath) {
    const e = manifest.assets[logicalPath];
    return typeof e === "object" ? e : {};
  },
};
```

### Nunjucks shortcode

Register in `.eleventy.js`:

```js
eleventyConfig.addShortcode("cdnImg", function (logicalPath, alt = "", cls = "") {
  const cdn = require("./_src/_data/cdn.js").default ?? require("./_src/_data/cdn.js");
  const url = cdn.resolve(logicalPath);
  const { width, height } = cdn.meta(logicalPath);
  const dims = width && height ? ` width="${width}" height="${height}"` : "";
  return `<img src="${url}" alt="${alt}" class="${cls}"${dims} loading="lazy" decoding="async">`;
});
```

Usage in a notes template / markdown:

```njk
{% cdnImg "course/bca/first-semester/computer-fundamental/notes/figures/addressing-modes.webp",
          "Direct vs indirect addressing modes", "rounded shadow" %}
```

The template references the **stable logical name**. When you update the image and re-run `sync`, only the manifest's hashed target changes — the template stays identical, and the browser fetches the new URL automatically.

> Note: the `cdnImg` shortcode adds hashed image URLs. This is separate from the existing `assetHashes.js` system (which hashes CSS/JS for the site's own static assets). Same *idea* (content hashing for cache-busting), different *scope* (remote CDN images vs. local site bundles).

## 10. Lifecycle: updates, orphans, cleanup

- **Update an image:** replace the file in `source/`, run `npm run sync`. New hash → new object uploaded → manifest points to it. The old hashed object still exists (harmless, immutable).
- **Orphan cleanup (optional):** `npm run prune` compares live bucket objects against the current manifest and lists objects no longer referenced. Default **dry-run**; require `--yes` to actually delete. Keep the previous 1–2 hashes around briefly so in-flight page caches don't 404.
- **R2 lifecycle rule (optional):** you *can* set a rule to expire objects under a `tmp/` prefix, but do **not** auto-expire content-addressed assets — they're meant to live indefinitely.

## 11. Security & ops notes

- API token is **bucket-scoped, read+write only**. It cannot touch other buckets or account settings.
- Secrets live in `.env` (local) or CI secrets. Never in the manifest, never committed.
- `manifest.json` is public information (just URL mappings) — safe to commit and even to publish at `cdn.tupapers.com/manifest.json`.
- The bucket is **public-read via the custom domain only**; the S3 API endpoint stays private (token-gated).

### Optional CI (GitHub Actions, in the asset repo)

On push to `main` when `source/**` changes:

```
checkout → setup-node 20 → npm ci → npm run sync
        → commit updated manifest.json (or upload it to R2)
```

Store `R2_*` as encrypted repo secrets. This makes asset publishing a `git push`.

## 12. TL;DR decision summary

- **Bucket:** `tupapers`, keys mirror the site: `course/<program>/<semester>/<subject>/notes/<category>/<file>.<hash>.webp`.
- **Hash:** SHA-256 of optimized WebP bytes, first 8 chars, **filename only** — folders stay clean.
- **Format:** PNG/JPG → WebP via `sharp`; SVG → `svgo` (kept as SVG).
- **Manifest:** flat `logical path → { key, width, height }`, committed to this repo.
- **Serve:** `cdn.tupapers.com` custom domain, `Cache-Control: immutable, max-age=1y`.
- **Consume:** Eleventy `cdnImg` shortcode resolves logical path → hashed URL at build.
- **Tooling:** standalone Node 20 CLI (`sharp` + `svgo` + `@aws-sdk/client-s3`), `npm run sync`.
- **Publish flow:** drop image in `source/` → `npm run sync` → commit `manifest.json`.
